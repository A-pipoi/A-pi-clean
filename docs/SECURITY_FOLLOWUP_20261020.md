# 续轮安全修复与边界

仅改独立副本；未部署、重启、访问生产凭据、调用模型/行情或运行生产归档。

## 本轮修复

1. 行情传输使用独立opener，拒绝301/302/303/307/308全部重定向，包括同主机跳转；不重放携Token的请求体。TLS证书校验未关闭。
2. 地址必须为HTTPS、有合法主机/端口，不允许userinfo、query、fragment、控制字符。显式配置的自定义HTTPS主机、路径、端口仍支持；配置即部署者指定的可信目的地，不等于任意主机已获安全审核。不得把未经审核的服务与真实Token组合使用。
3. 响应最多读取32 MiB加1字节，超过拒绝；无效JSON/编码转换为不含响应内容的ProviderError，错误不重试。错误正文可能包含Token，因此不加入异常消息。
4. 正式服务验证、HTTP回测安全验证、真实LLM验证、拆分计划及崩溃辅助验证脚本不再依靠可被优化掉的assert。最小导入测试的子程序亦改为显式异常。没有执行真实LLM验证流程。
5. 归档辅助脚本的PRAGMA列名按SQLite标识符规则双引号转义。内存数据库的引号/逗号列名回归通过；没有运行生产归档。

## 测试边界

定向测试覆盖非法地址预算前拒绝、所有重定向类别、受信任自定义HTTPS路由保留、独立opener策略、响应大小和脱敏错误，以及优化级别0/1/2下的显式拒绝分支。脚本分支测试只抽取单个函数/拒绝分支，不执行真实服务、真实模型或真实交易流程，不能据此宣布正式因子验收通过。

一次定向命令误写不存在的测试文件，收集0项且退出4；后已改用实际存在的测试路径，80项通过。全量首次出现4项Windows沙箱权限失败，不能写作通过；批准后的隔离全量结果另记交付说明。

Ruff保持407条原规则；Mypy按项目配置检查quant（194文件）。临时把scripts/deep_factor同时作为Mypy源根的命令因重复模块名中止，不把它写成全站类型检查通过；脚本另以Ruff、语法及专项回归验证。
